# 全量验收的单轮复用

2026-09-08根据已有约45分38秒的完整阶段3/2/1/0批次优化验收编排。当前改动没有运行测试，没有新的耗时或通过率实测；阶段4专项及覆盖率本来也不包含在这45分钟中。没有改变产品调试逻辑。

## 入口与复用范围

管理员64位PowerShell运行：

```powershell
./eng/verify-all.ps1 -NodePath 'C:\Program Files\nodejs\node.exe' -CodePath 'C:\Program Files\Microsoft VS Code\Code.exe'
```

默认Debug/Release，支持 `-Configuration Debug|Release`。先完成阶段4-1/2/3，再运行完整阶段3及其阶段2/1/0回归，包括真实Service/IIS和VS Code。这个入口不替代阶段4的变更行覆盖率采集与审核。

已有 `verify-stage3.ps1`、`verify-stage3-4.ps1`、`verify-stage2.ps1`、`verify-stage1.ps1` 也默认创建自己的单轮上下文；嵌套运行沿用父轮上下文。单独执行其他专项时保持原执行行为。各入口仍按原门槛失败即停止。

| 准备工作 | 本轮行为 |
| --- | --- |
| 解决方案及其中的探针、样例项目构建 | 每配置一次 `--no-incremental`，随后复用相同产物 |
| 普通单元测试及其过滤子集 | 每配置完整套件一次，成功后覆盖后续过滤子集；第一次请求过滤子集也执行完整套件 |
| MCP/DAP发布与Engine依赖复制 | 每入口、配置、输出路径一次 |
| 阶段0-1 | 每配置真实执行一次，包括Windows PDB与双架构WinForms启动/退出验证 |
| Service/IIS覆盖率harness构建 | 每配置一次；权限与IIS覆盖率仍分别采集 |

每次复用检查源码/脚本/根构建输入指纹和完整产物文件集合、长度、修改时间，结束前统一复核SHA256。上下文绑定本轮仍存活的创建进程，结束后关闭，下一次调用创建新目录；输入或产物变化会失败，不通过重建、重试或历史结果拼接得到通过。

只识别现有默认构建、普通单元测试参数和脚本中既有的五种过滤表达式。自定义MSBuild参数、非解决方案项目（专用覆盖率harness除外）、插桩/收集器及未知选项/过滤表达式执行原命令，不复用测试结果。不支持共享同一输出目录的并行验收。

## 保留的实际验证

双配置、双架构、原生/MCP/DAP/CLI/VS Code场景、生命周期故障矩阵、100次Continue配对、异常压力等仍执行。Service/IIS五个专项各自安装并清理专属环境，覆盖部署、延迟删除、中断恢复、权限、服务、符号和回收；这些状态不能作为普通缓存复用。正常采集和覆盖率采集也不能互相代替。

本次主要消除多层脚本反复构建/发布及反复执行同一完整单元套件的开销。没有据此承诺45分钟能缩短到某个数值，需后续授权运行后比较。

## 证据与耗时

共享准备保存在 `artifacts/validation-runs/<runId>/`。每份成功准备清单包含原日志、时间、产物元数据和SHA256；`reuse.jsonl` 记录复用关系，子步骤日志输出 `REUSED` 和原始日志路径。复用不冒充重新运行，完整归档必须同时包含本轮共享准备目录和各专项结果目录。

监督器为每个步骤生成 `.log.timing.json`，直接记录起止UTC、墙钟秒数、退出码、是否超时和强制清理数量。统计顶层步骤时不要再加上其子步骤；细分构建/测试时使用对应叶子步骤。最终 `verification.json` 记录输入和产物核验，`verify-all.ps1` 的 `result.json` 记录整体结果。

原始日志和这些逐步骤清单仅保存在被忽略的 `artifacts/`。提交Git时提炼一份结果摘要和归档位置/哈希，遵守 [AGENTS.md](../../AGENTS.md) 的证据保留规则。

## 编排边界检查

`tests/ValidationScripts/Reuse.Tests.ps1` 使用隔离目录和假的命令执行器，覆盖构建/单元复用、配置隔离、插桩及未知过滤参数透传、输入变化、相同时间/长度下的内容变化、输出集合变化、关闭批次拒绝、失败不缓存与独立运行。可在新的PowerShell进程中执行；本次按用户要求仅解析了该脚本，没有运行。
