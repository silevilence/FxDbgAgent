# 阶段3-4e：IIS 动态模块、多域及回收

使用独立 `Stage3-4-lifecycle` 环境，双架构池与实际 w3wp 承载全部用例；复用现有 MCP、Host、Engine 的模块加载、域卸载、符号重新加载及执行控制。夹具只有固定 HTTP 动作，不能执行任意代码或操作任意路径。

## 验证设计

- IIS 预热不加载 late 磁盘库；预设断点为 pending，请求触发加载后自动绑定并实际停止。另设置尚未请求过的 `late.aspx` 断点，首次动态编译时停止并核对仓库路径与行号。测试站点禁用批量页面编译，保持影子复制和 Windows PDB。
- 同一 worker 建立两个同名子 AppDomain，均加载同一磁盘程序集。限定域断点只命中选定域，栈和变量携带该域身份；重建后旧域/模块消失，旧限定断点回 pending，未限定域断点在新域重绑定。旧帧和引用分别按既有错误语义拒绝。
- Reflection.Emit 创建仅内存、无 PDB 的模块并执行固定方法；模块可枚举，明确报告符号不可用及诊断，会话保持可用。没有承诺支持任意动态 IL 源码调试。
- 一个实际挂起请求保留旧 worker，再对专属池正常 recycle；AppCmd 必须同时列出旧/新 PID，原会话仍指向旧 PID。释放旧请求后等待旧会话终止，再显式附加新 PID，暂停/分离后验证新请求成功。
- 专属池的 ping、空闲超时和周期回收设置先保存，仅测试期间调整；finally 使用独立清理期限逐项恢复并核对原值。部署脚本随后移除清单资源，不使用 iisreset 或批量终止 worker。

入口 `eng/verify-stage3-4e.ps1` 默认 Debug/Release。机器证据位于 `artifacts/stage3-4-validation/lifecycle-result.json`、`iis-lifecycle-{配置}.json`，记录断点/模块/域快照、回收重叠 PID 及原池配置，各监督步骤有日志和进程清单。快速审核补齐配置调整的 try/finally 边界及独立恢复期限，避免 MCP 建连或未完成 HTTP 请求失败时跳过配置恢复。
