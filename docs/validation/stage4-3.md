# 阶段4-3：条件断点与快速审核

日期：2026-09-08。需求为ROADMAP阶段4-3与已批准ADR-004；实现基点fbbec36。4-4仍为不实施决策。

## 实现

Core的BreakpointCondition统一验证=N/>=N及受限表达式，BreakpointManager按逻辑断点累计真实启用命中，次数条件与表达式AND。Interop在当前原生回调帧复用4-1的只读读取，不调用公开stopped求值入口，不创建用户帧/引用，不执行目标代码。false沿既有回调Continue路径继续，只有需要停止时才调用StopAt；错误/非bool/超时保守停止，并在conditionDiagnostic保留脱敏分类。

BreakpointInfo新增condition、hitCondition、hitCount、conditionDiagnostic；重绑定、模块重载、启停均保留计数，删除重建重置，状态仍四种。CLI/MCP/DAP复用同一策略。DAP先验证整份列表，保留同文件未变条目的ID/计数，避免增加其他断点重置计数；诊断通过标准Breakpoint.message显示，隐藏命中不引起计数变化事件洪泛。

## 快速审核

| 方面 | 结论 |
| --- | --- |
| 需求满足 | 次数阈值、表达式、AND、false、失败恢复、真实模块重载及四入口均有测试 |
| 质量 | 回调只入队，条件在单调度线程，隐藏命中无StopAt/用户引用；诊断无表达式/值，250ms预算有可控慢读取单测 |
| 规范 | Core定义策略与计数，Interop只读当前帧，入口仅转换；没有新增CLR Eval、写入或Continue路径 |

🔴 设计中已处理的阻塞风险：DAP原列表全量删除重建会使命中计数在编辑其他断点时重置；现在按位置/条件保留同一逻辑断点。测试在每次真实停止重新提交同一断点及另一条false断点，断言ID不变且阈值仍正确。

MCP测试区分“已发生真实停止但事件尚未完成operation”的短暂状态；此时只接受预计命中次数对应的真实停止。未匹配条件不能产生快照停止或operation完成。测试不把两个异步通知的合法先后关系误判为内部停止泄漏。
