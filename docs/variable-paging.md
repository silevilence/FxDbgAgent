# 对象与数组分页

MCP `debug_variables` 和 CLI `variables` 共用同一读取器。先用实际停止帧的 `frameId` 获取根变量（需要避免预展开时设 `maxDepth=0`），再携带结果中的 `referenceId`、`start`、`count` 读取成员。`totalMembers` 是直接子成员数，下一页起点为本页起点加返回的顶层成员数；起点达到总数时返回空数组。数组的下标是从零开始的线性位置，包含多维数组。

默认 `start=0,count=100,maxDepth=1,maxStringLength=256`；深度允许0～8、数量1～1024、字符串长度1～32768。数量预算涵盖本次结果的全部顶层及递归子项，不是给每个子对象各1024项。字符串截断包含省略号；长度为1时截断结果仅为省略号。负起点、非法数量/深度/长度返回 `invalid_request`；很大的合法起点返回空页，不发生整数溢出。

数组按请求位置直接读取，对象只读取所请求的字段值；为确定字段名称、顺序与数量可以缓存有界字段元数据，不遍历整个对象图或调用Getter、ToString。循环对象返回同一引用，不递归展开。值为空、不可获取和优化掉分别报告。

每次停止最多保存10000个对象引用，单类型字段元数据最多10000项、继承层级最多128层。超过边界明确返回不可获取状态及原因，不淘汰仍在使用的引用，也不无界占用内存。超过10万成员的数组或对象图可以分页读取；这不意味着一次停止中可保留超过10000个不同对象句柄。运行操作使旧帧与引用失效，必须重新获取。协议体积超限时缩小页或字符串长度，不重试执行命令。

取消信号传入字段元数据、数组/对象成员循环及递归读取；正在执行的底层COM调用仍需返回后才能观察取消。MCP取消、超时及分离语义沿用[工具契约](mcp-tools.md)，不得将取消误认为目标仍停在原位置。

性能验收由 `eng/verify-stage3-1.ps1` 驱动真实MCP、Windows PDB和双架构FX进程：100001元素数组首/中/尾页各测10次，预热后P95≤1秒、单次≤5秒；单独记录首次变量读取耗时。嵌套对象图包含101个1001元素数组（101101个叶成员），逐个抽取尾页并验证；机器结果写入 `artifacts/stage3-validation/paging-<Configuration>.json`。测试还覆盖循环、截断、越界、失效引用及读取不执行用户代码。此阈值为项目约定，不是需求§10.3原有数值。
